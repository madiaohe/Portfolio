# Ambient Dial：浏览结构审查与替代方案

日期：2026-09-05。范围：当前桌面详情页的首屏、正文、细节、结尾，与当前 About 页比较。以下截图均在本次审查中从同一浏览器采集，保存后逐一检查。未修改页面实现。

## 判断

当前页面有章节清单，但缺少浏览时持续可见的阅读框架。布局和编号多次改变，大标题表达设计态度，具体问题与设计决定之间的关系偏弱。建议沿用 About 的固定目录和统一内容轴，改为由问题推进的项目叙述。

## 1. 项目入口：视觉统一，信息定位偏弱

![项目入口](/Users/xianyu/Workspace/IDEA/portfolio/artifacts/project-detail-audit/01-entry.png)

优点：继承了网站的字体、留白与导航。问题：项目名称与感性口号占据大部分首屏，未直接说明物件的用途；章节导航位于大图之后。读者开始浏览时没有获得完整的内容地图。

## 2. Overview 与 Approach：阅读顺序不稳定

![正文结构](/Users/xianyu/Workspace/IDEA/portfolio/artifacts/project-detail-audit/02-overview.png)

右侧标题和双栏正文之后，内容突然变成跨全页三栏。章节 02 下又出现 01/02/03，层级容易混淆。目录离开视口后，没有当前位置反馈。Overview 对应正文 The idea，Approach 对应 Design direction，同一章节使用两套名称，增加识别成本。

## 3. Details：图片清晰，但与论点分离

![产品细节](/Users/xianyu/Workspace/IDEA/portfolio/artifacts/project-detail-audit/03-details.png)

两张图片均裁切自封面同一张图，增加篇幅但新增信息有限。前一章节提出直觉控制，本章又独立展示旋钮，读者需要自行将论点与图片连接。建议将每张图放回对应设计决定之下，并解释其具体作用。

## 4. Reflection：结束位置明确，实质总结较弱

![结尾](/Users/xianyu/Workspace/IDEA/portfolio/artifacts/project-detail-audit/04-reflection.png)

优点：明确标注概念性质，没有虚构上线数据。问题：结尾重复形式与控制方向，缺少可被读者快速复述的结论。后续应区分已形成的方案与待验证假设；没有实际资料时保持简短。

## 5. About 对照：结构更容易追踪

![About 对照](/Users/xianyu/Workspace/IDEA/portfolio/artifacts/project-detail-audit/05-about.png)

年份目录、公司节点、角色说明和项目子项共用稳定的内容轴。位置、字号与缩进共同表达层级。内容更多，但读者更容易识别归属。借用这种组织方式，不必把项目叙述伪装成时间线。

## 替代方案：固定目录 + 单列项目叙述

左侧保留项目名与四个章节；当前章以文字状态和细标记共同识别。右侧所有标题、正文和图像共用起始线。节点仅用于章节，不给每段文字添加装饰节点。

1. Project：这是什么、用于什么场景、我的工作范围；一句具体介绍、紧凑元信息、一张完整主图。
2. Problem：哪一个具体动作存在阻碍；以场景说明问题与限制，避免空泛宣言。
3. Design decisions：为什么采用这个方案；每项按“问题或约束 → 决定 → 对应图示 → 预期作用/待验证点”组织。取消独立的三栏理念和细节图库。
4. Outcome：做到哪一步、仍有什么不确定；明确概念状态、已完成内容与后续验证。

将当前约百像素的项目标题收至约 48–56px，章节标题约 28–34px。正文单列，图像不超出内容主栏。全页仅章节使用数字；目录和正文使用同样的名称。

手机端收为单列，目录成为紧凑的可展开章节导航；正常滚动，主要内容不折叠。减少动效时取消跟随动画。以上为交互提案，尚未实现或验证。
