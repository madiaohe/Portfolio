# Benji 首页间距审阅

日期：2026-09-11。范围：`https://benji.org/` 首页与本项目首页的排版、间距和响应式对照。本轮只分析，没有修改应用代码。

## 审阅步骤

1. Benji 桌面端（1440 × 1000）：健康。内容列窄而集中，页面节奏由少量稳定的间距值构成。
2. Benji 移动端（390 × 844）：健康。缩小顶部留白与列表标题缩进，正文节奏保持不变。
3. 本项目桌面端（1440 × 1000）：可读，但纵向区块过度分离，首屏信息利用率较低。
4. 本项目移动端（390 × 844）：可读，但头像、身份、近况和列表之间的空白带较多，列表缺少连续的结构线索。

## Benji 的间距为什么显得稳

### 1. 只有少量重复数值

主要节奏几乎可以归纳为 `4 / 8 / 16 / 40 / 48 / 80`：姓名和更新时间间 4px，header 底部 8px，每段顶部 16px，列表行约 40px，正文进入 Writing 为 48px，桌面顶部为 80px。层级来自数值倍增，而不是每个区块单独设一套距离。

### 2. 内容列足够窄

桌面正文只有 550px。14px 字号配合 20px 行高，使每行有合适的字符数，长简介仍然像一个完整叙事块。当前首页 644px 内容列配 16px 字号，视觉横向跨度更大，区块间再使用 128px，会让页面显得松散。

### 3. 空间被分成“内部节奏”和“章节节奏”

正文内部固定 16px；从简介切到 Writing 固定 48px。Benji 没有在相邻正文元素之间插入大空白，只有真正换章时才放大距离。

### 4. 列表使用网格和细线代替大间距

列表由“年份 / 标题 / 日期”三列组成。桌面标题列从 108px 开始，移动端改为 48px；日期贴右。行之间没有额外 gap，而是用非常浅的 1px 分隔线维持连续性。因此列表紧凑但不拥挤。

### 5. 移动端只改变外框和列表缩进

断点为 768px 和 520px。页面顶部从 80px 收到 32px，水平边距从 16px变为 24px，列表标题缩进从 108px 收到 48px；正文的 14/20 和 16px 段落节奏保持不变。响应式行为少，画面因此稳定。

## 当前首页的主要差异

1. Header 本身高 112px，之后再加 128px 底部间距；移动端也保留 128px。身份和近况被切成两个相距很远的画面。
2. 桌面每个主要分区统一间隔 128px。这个数值适合强调少量大章节，但当前 Projects、Writing、Contact、More 都使用它，页面形成重复的大空白带。
3. 项目和文章都采用“标题 / 日期 + 第二行描述”。桌面每项约 72.5px，移动端项目之间另有 28px gap；当文章达到十余条时，页面长度迅速增长。
4. 分区标题和正文都以 16px、较深颜色呈现，主要依赖空白表达层级。Benji 则用浅色标签、分隔线和列对齐表达层级，因此不需要大空白。

## 建议借鉴，而不是直接复制

### 第一轮改动建议

- 将桌面内容列从 644px 收到约 550–580px。
- 将桌面顶部从 128px 收到约 80px；移动端从 80px 收到 32–48px。
- 将 Header 到 Today 的 128px 收到约 48–64px。
- 将主要分区间距统一收敛到 48–64px，不再区分桌面 128px与移动端 64px 两个跨度很大的节奏。
- 将 Projects / Writing 标题处理为较轻的 14px 标签，并考虑增加浅分隔线。
- 列表从“大卡片式双行 + 外部 gap”改成连续行。若保留描述，每行可控制在约 56–64px；普通文章可只显示标题与日期，控制在至少 44px 的可点击行。
- 可以引入 Benji 的年份分组，但不必强行用于项目；项目仍可保留描述，文章更适合紧凑的年份目录。

### 不建议照搬

- Benji 的次要文字实际接近 `rgba(0,0,0,.4)`，截图中对比度偏低。本项目应保留更清晰的 muted 色。
- Benji 的移动列表行约 40.5px，触控舒适度有限。本项目应维持至少约 44px 的有效点击高度。
- 不必复制顶部白色渐隐遮罩、粉色 New 手绘标记或整套 14px 排版；我们要借的是间距系统和列表骨架。

## 结论

最值得借鉴的不是某一个具体 margin，而是这套规则：**窄内容列、正文 16px 小节拍、章节 48px 大节拍、列表用网格和细线组织、移动端只收外框不重写节奏。**

本项目下一轮首页调整可以围绕这五条落地，同时保留头像、双语、深浅主题和更好的文字对比度。
